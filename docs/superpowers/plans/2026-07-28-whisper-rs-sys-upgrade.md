> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `pnpm tauri:dev` build and launch the Meetily Tauri app on Windows x64 by upgrading `whisper-rs` to 0.14.4 (with `whisper-rs-sys` 0.13.1) and fixing the surrounding build environment.

Two environment-level fixes (MSVC UTF-8 flag injection, `x86_64` target triple, `llama-helper` sidecar build) added to `scripts/quickstart.bat` so the local dev workflow matches what CI already does. No source code changes unless `whisper-rs 0.14.4` introduced API churn — in that case, minimal adjustments in `whisper_engine.rs` driven by compiler errors.

**Tech Stack:** Rust (cargo), Tauri 2.x, whisper-rs 0.14.4, whisper-rs-sys 0.13.1, pnpm, MSVC, cmake.

**Target versions (verified against crates.io 2026-07-28):**

- `whisper-rs-sys = "0.13.1"` (transitive, satisfies `^0.13` from whisper-rs 0.14.4)

## Task 3: Update scripts/quickstart.bat with env injection + llama-helper build

**Files:**
- Modify: `scripts/quickstart.bat`

- [ ] **Step 1: Read current quickstart.bat**

The current file is at `scripts/quickstart.bat`. Read it fully so you have the exact context for the edits below. (It is 102 lines as of 2026-07-28.)

- [ ] **Step 2: Add `set` lines for env vars after the `pnpm_ok` label**

In `scripts/quickstart.bat`, find the block that starts with `:pnpm_ok` (around line 55). The current block looks like:
```bat
:pnpm_ok
call :log "using pnpm: %PNPM%"
```

Change it to:
```bat
:pnpm_ok
call :log "using pnpm: %PNPM%"

REM Force x86_64 target (matches project / CI; host rustup default is aarch64)
set "CARGO_BUILD_TARGET=x86_64-pc-windows-msvc"

REM Force MSVC to read source as UTF-8. whisper.cpp contains CJK
REM punctuation that GBK-codepage cl.exe misreads as invalid literal
REM suffixes (C3688). /utf-8 is harmless if the file is ASCII-only.
set "CMAKE_C_FLAGS=/utf-8"
set "CMAKE_CXX_FLAGS=/utf-8"
```

- [ ] **Step 3: Add the llama-helper sidecar build step after the existing `pnpm install` block**

Find the existing block (around line 65–75) that checks for `node_modules` and either installs or skips:
```bat
if not exist "%FRONTEND%\node_modules" (
  call :log "running pnpm -C %FRONTEND% install --frozen-lockfile"
  call "%PNPM%" -C "%FRONTEND%" install --frozen-lockfile 1>>"%LOG%" 2>&1
  if errorlevel 1 (
    call :err "pnpm install failed (see %LOG%)"
    call :pause_keep_open
    exit /b 1
  )
) else (
  call :log "frontend\node_modules present; skipping install"
)
```

Insert the following block **immediately after** this block (before the `call :log "starting pnpm ... tauri:dev"` line):
```bat
REM Build llama-helper sidecar (matches what CI does in build-windows.yml).
REM Tauri fails to launch without binaries\llama-helper-<target>.exe.
if not exist "%FRONTEND%\binaries\llama-helper-x86_64-pc-windows-msvc.exe" (
  call :log "building llama-helper sidecar (release, CPU-only)"
  cargo build --release -p llama-helper 1>>"%LOG%" 2>&1
  if errorlevel 1 (
    call :err "llama-helper build failed (see %LOG%)"
    call :pause_keep_open
    exit /b 1
  )
  if not exist "%FRONTEND%\binaries" mkdir "%FRONTEND%\binaries" 1>>"%LOG%" 2>&1
  copy /Y "%CD%\target\release\llama-helper.exe" "%FRONTEND%\binaries\llama-helper-x86_64-pc-windows-msvc.exe" 1>>"%LOG%" 2>&1
  if errorlevel 1 (
    call :err "copying llama-helper.exe to binaries\ failed (see %LOG%)"
    call :pause_keep_open
    exit /b 1
  )
  call :log "llama-helper sidecar ready"
) else (
  call :log "binaries\llama-helper-x86_64-pc-windows-msvc.exe present; skipping sidecar build"
)
```

- [ ] **Step 2: Launch quickstart in background**

```bash

echo $! > /tmp/quickstart.pid
```

Or use `run_in_background: true` in your tool. The script will:
1. Check `node`/`pnpm`/`cargo`
2. Run `pnpm install --frozen-lockfile` (uses fresh lock from Task 2)
3. Build `llama-helper` (Task 3 addition)
4. Launch `pnpm tauri:dev` which kicks off `cargo build` for meetily

This will take 5–15 minutes the first time (whisper.cpp cmake build is the slowest step).

- [ ] **Step 3: Monitor progress**

```bash
sleep 60 && tail -30 quickstart.log
```

Look for these markers (in order):
- `using pnpm: ...` (env vars are now set)
- `running pnpm -C ... install --frozen-lockfile` (then either success or skip)
- `building llama-helper sidecar (release, CPU-only)` (new Task 3 step)
- `llama-helper sidecar ready` (confirms copy succeeded)
- `Starting Tauri dev (Ctrl+C to stop)...`
- `Compiling whisper-rs-sys v0.13.1` (confirms new sys is in play)
- `Compiling whisper-rs v0.14.4` (confirms new wrapper is in play)

- [ ] **Step 4: Look for known error markers in the log**

```bash
grep -E "C3688|E0609|unknown field|error\[|failed to run custom build" quickstart.log | head -20
```

Expected: empty (or only warnings). If you see `C3688`, the UTF-8 flag did not propagate — see Troubleshooting below. If you see `E0609 unknown field`, sys 0.13.1 still produces opaque bindings — see Task 5.

- [ ] **Step 5: Look for success markers**


Expected:
- `Compiling tauri v2.x` then later
- `Finished` line from cargo
- `ready in ...ms` from Vite (the Next.js dev server)
- A native Tauri window should pop up

- [ ] **Step 6: Confirm no process died**

```bash
ps -ef | grep -E "tauri|cargo|node" | head -10
```

Expected: at least one cargo process still running (Tauri dev keeps cargo alive for HMR / IPC).

**Troubleshooting:**
- If `C3688` reappears: confirm `CMAKE_C_FLAGS` shows up in `cl.exe` invocation by grepping the log: `grep "cl.exe.*utf-8" quickstart.log`. If missing, the `set` lines didn't propagate — check `:pnpm_ok` block is reached.
- If `E0609` reappears: sys 0.13.1 bindgen is also opaque. Fall back to setting `WHISPER_DONT_GENERATE_BINDINGS=1` in `:pnpm_ok` (forces sys to use its bundled field-expanded `src/bindings.rs`). Document the fallback if it works.
- If llama-helper copy fails: check `target/release/llama-helper.exe` exists and `%CD%` resolved correctly at the time of `copy`.
