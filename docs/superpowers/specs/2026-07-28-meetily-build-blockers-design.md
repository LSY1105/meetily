# Design: Fix 3 pre-existing meetily/llama-helper build blockers

**Date**: 2026-07-28
**Branch**: devtest
**Status**: Approved

## Context

The whisper-rs-sys Windows build fix (commits up to `8228cca`) unblocked the
whisper-rs portion of the build. Three independent blockers remain that
were visible in `git status` at the start of this session as pre-existing
modifications to files. They block `cargo check` from finishing and
prevent Tauri from launching.

## Problem

1. **`post_processor.rs:546`** — `static TERMS_LOCK` declared inside
   `impl Default for PostProcessor` block. Rust allows `static` in
   modules but not as an "associated" item of an impl block. The error
   is `error: associated 'static' items are not allowed`. The file also
   has 7 `#[test]` functions and a `set_terms_for_test` helper that
   belong inside `mod tests` (currently misplaced inside the impl).

2. **`retranscription.rs:537`** — trailing `}` at end of
   `start_retranscription` causes `error: unexpected closing delimiter:
   '}'`. The block that calls `tokio::spawn(async move { ... commit_speaker_labels ...})`
   has one too many closing braces at its end.

3. **`llama-helper/Cargo.toml:10`** — `llama-cpp-2 = "=0.1.146"` is
   pinned exact, but cargo resolves `llama-cpp-sys-2 = 0.1.152`. The
   wrapper at 0.1.146 references symbols not present in sys 0.1.152
   (specifically the `llama_rs_chat_*_oaicompat` family, `LLAMA_PARAMS_FIT_STATUS_*`,
   `llama_memory_breakdown_print`, `llama_params_fit`). Result:
   `error[E0425]: cannot find function ... in crate 'llama_cpp_sys_2'`.

These are pre-existing issues, not introduced by the whisper-rs work.

## Goal

`pnpm tauri:dev` builds and launches the Meetily Tauri app on Windows
x64. Specifically: `cargo check` passes for `meetily`, `cargo build`
passes for `llama-helper`, and `cargo build` for the full workspace
succeeds.

## Approach

### Fix 1: post_processor.rs — relocate misplaced test code

The protected-terms test code (PR-55, lines 541-632 in HEAD) is inside
`impl Default for PostProcessor` but should be inside `mod tests` (which
closes at line 534). Move it as a single block.

**Files:**
- Modify: `frontend/src-tauri/src/audio/post_processor.rs`

**Change:** Cut lines 541-632 and paste them inside `mod tests`,
between line 533 (last test in the original `mod tests`) and line 534
(closing `}` of `mod tests`). Result:
- `impl Default for PostProcessor` contains only `fn default() -> Self`.
- `mod tests` contains the original tests plus the PR-55 protected-terms tests.

The `use super::*;` already present at the top of `mod tests` ensures
the relocated code can see `PostProcessor`, `set_protected_terms`,
`set_hotwords_for_llm`, `read_hotwords_for_llm`, etc.

### Fix 2: retranscription.rs — remove the extra closing brace

**Files:**
- Modify: `frontend/srcrc-tauri/src/audio/retranscription.rs`

**Change:** Delete one `}` from the trailing portion of
`start_retranscription` (around lines 528-529). The exact line is
whichever one has stray indentation after the diarization block.

The fix is driven by `cargo check` output: any extra `}` causes the
"unexpected closing delimiter" error. The implementer should
incrementally delete one `}` at a time and re-run `cargo check` until
the file compiles, leaving the function's closing `}` at the actual
end of the function (after `Ok(RetranscriptionResult { ... })`).

### Fix 3: llama-helper — drop exact pin on llama-cpp-2

**Files:**
- Modify: `llama-helper/Cargo.toml`
- Modify: `Cargo.lock` (regenerated by cargo)

**Change:** `llama-cpp-2 = "=0.1.146"` → `llama-cpp-2 = "0.1"`.
This lets cargo resolve to a wrapper version whose internal references
match the `llama-cpp-sys-2 = 0.1.152` it's already pulling in.

If the resolved wrapper version changes any function signatures that
`llama-helper/src/main.rs` calls, those call sites need updating. This
is compiler-error-driven — fix only what fails. Estimate 0-10 lines.

## Files Changed

| File | Change |
|---|---|
| `frontend/src-tauri/src/audio/post_processor.rs` | Move lines 541-632 from inside `impl Default` to inside `mod tests` (cut + paste) |
| `frontend/src-tauri/src/audio/retranscription.rs` | Delete one extra `}` at end of `start_retranscription` |
| `llama-helper/Cargo.toml` | `llama-cpp-2 = "=0.1.146"` → `"0.1"` |
| `Cargo.lock` | Regenerated by `cargo build` |
| `llama-helper/src/main.rs` | Possibly — only if `llama-cpp-2` API changes between 0.1.146 and the resolved version |

## Validation

1. **post_processor.rs**: `cargo check --manifest-path frontend/src-tauri/Cargo.toml --target x86_64-pc-windows-msvc` — should produce no error from `post_processor.rs`.
2. **retranscription.rs**: same `cargo check` — should produce no error from `retranscription.rs`.
3. **llama-helper**: `cargo build -p llama-helper --target x86_64-pc-windows-msvc --release` — should produce a working binary at `target/x86_64-pc-windows-msvc/release/llama-helper.exe`. Then verify by copying it to `frontend/src-tauri/binaries/llama-helper-x86_64-pc-windows-msvc.exe`.
4. **End-to-end**: `scripts\quickstart.bat` should now succeed at the llama-helper build step AND the meetily build step. Tauri window opens.

## Risk Register

- **post_processor.rs relocation**: Risk that one of the relocated items
  has a different scope requirement than `mod tests`. Mitigation: the
  tests use `super::*` already (line 449).
- **retranscription.rs brace deletion**: Risk of deleting the wrong `}`
  if the indentation lies. Mitigation: validate by `cargo check` after
  each deletion attempt.
- **llama-cpp-2 version bump**: Risk of API changes between wrapper
  versions. Mitigation: compile-error-driven fixes in `main.rs`.

## Non-Goals

- Not refactoring audio module structure
- Not changing whisper-rs work (already done)
- Not modifying quickstart.bat (already updated)
- Not touching pre-existing modifications to other files in git status
  (e.g. `whisper_engine.rs`, `llm_health.rs`, `summary/llm_client.rs`,
  etc.) unless they block the build
